# Design Docs

`/docs` is the single source of truth for business requirements, as declared in `AGENTS.md`.

## Convention

- One design doc per feature or initiative, in Markdown.
- File name: `NNN-kebab-case-title.md`, where `NNN` is the next unused zero-padded sequence number (e.g. `001-onboarding-flow.md`).
- Apply review notes and status updates directly in the corresponding design doc — do not create separate review/audit/analysis files.
- When a design doc is implemented, keep it in place as the historical record; do not delete it.

This directory is intentionally created empty on fork/clone — forks fill it in with their own design docs as work begins.
